## 4. 本轮补齐内容

1. 新增共享输入校验并接入单体与微服务：商品必填/价格/库存/媒体、订单正整数数量和完整收货地址、
   评价标识/星级/正文/图片、资料格式和新密码长度；同时补充单元和控制器“不写库”拒绝断言。
2. 前端订单与公开店铺组件测试由 3 条扩到 7 条，增加未登录、加载失败、支付/确认状态和未完成订单
   禁止评价。
3. 微服务网关测试显式扩展到 UC01-UC12，公开 API 套件由 13 项输出扩到 15 项输出。
4. 新增隔离微服务集成运行器，测试不再依赖人工设置数据库密码或占用固定 3306 端口。
5. 新增 Docker/Compose/CI/K8s 打包测试和性能/HPA/故障/部署证据完整性测试。
6. CI 前端阶段加入 lint，镜像构建同时依赖安全扫描；任一门禁失败都不会进入镜像或部署阶段。
7. Compose 移除全局 `container_name`，数据库宿主端口可配置，性能脚本改为按 Compose 服务解析容器，
   可与旧环境并存复测且不删除旧数据卷。
8. 单体后端补齐 `/api/live`、`/api/ready`、`/api/health`、`/api/version`，区分三类 Kubernetes
   探针并提供迁移失败自动重试。
9. 单体 Kubernetes MySQL 增加 Retain PV/PVC；单体和微服务 MySQL Deployment 使用 `Recreate`，
   避免滚动更新时两个 MySQL Pod 同时挂载同一数据卷。

## 6. 性能、HPA 与故障证据

- 性能对比 CSV 有 18 行：单体/微服务 × list/search/detail × 3 轮；对应保留 18 份 k6 JSON、
  18 份控制台输出、18 份容器资源时间线和固定数据一致性校验，错误率均为 0。
- HPA 时间线有至少 20 个样本，实测 `1 → 3 → 5 → 1`，997 个请求、1994 个业务断言、
  P95 1124.54ms、错误率 0。
- 商品服务故障时商品接口 503、订单依赖检查 206，用户/订单/网关保持存活；恢复后商品和网关均
  HTTP 200，HPA 恢复为 1/5。
- 上述证据现在由 `EVIDENCE-*` 自动测试检查，缺文件、缺轮次、未扩容、未恢复或错误率异常都会失败。

## 7. 非阻断剩余风险

- 纯单元口径的后端行覆盖率为 58.63%，原因是大量真实数据库主流程由 32 条 API 集成测试而不是
  mock 控制器测试覆盖；课程材料未规定后端覆盖率阈值，功能路径已由真实 MySQL 和页面 E2E 验证。
- backend 及三个 Sequelize 业务服务的生产依赖审计各有 2 个 moderate，来源为 Sequelize 间接
  使用的 uuid；npm 当前只给出降级到旧 Sequelize 主版本的破坏性“修复”，因此未强制降级。
  高危和严重漏洞为 0，CI 会继续在 high 门槛阻断。
- 本轮确认的是本机 Compose 与 Kind 的可部署、可运行状态；历史公网 GitHub Pages/Codespaces 地址
  不作为本轮验收依据。
