## 流水线失败策略

`.github/workflows/ci-cd.yml` 的发布顺序是：

1. `backend-test` 执行后端单元/安全测试及完整 API 测试。
2. `frontend-build` 执行前端单元测试后再构建。
3. `browser-e2e` 执行页面完整业务流程。
4. `microservice-test` 执行各微服务及网关集成测试。
5. `docker-build` 显式依赖以上四个任务；任何测试失败，镜像不会构建或发布。
6. Kubernetes 清单检查和部署任务依赖 `docker-build`；测试失败时不会进入部署阶段。

因此流水线符合“测试失败必须停止，不能继续发布镜像或部署”的课程要求。
