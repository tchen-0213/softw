# 2026-08-31 D6-02 微服务公开 API 与全量回归验收记录

## 1. 任务与结论

对应 GitHub Issue：[D6-02 #16](https://github.com/tchen-0213/softw/issues/16)。

本次把三个业务微服务经 API Gateway 暴露的接口整理为机器可读清单，并增加代码、测试、文档和运行时四重校验：

- 48 个 Express 业务路由和 1 个静态文件路由，共 49 项公开业务 API，均有归属服务和自动化编号。
- UC01-UC09 均明确覆盖 MAIN、ALT、ERR；页面端继续由 4 条 Playwright 流程组合覆盖 E2E-TC01 至 E2E-TC09。
- API 测试通过 `http://127.0.0.1:8081` 网关执行，页面测试使用 `http://127.0.0.1:8082` 微服务前端。
- MySQL 使用 `softw_users`、`softw_catalog`、`softw_orders` 三个独立 Schema；测试数据每次使用时间戳和 UUID 生成，可重复运行。
- CI 无论成功或失败都会上传环境信息、API 原始输出和 Playwright HTML 报告；失败时另外保存 Compose 日志。

完整接口表和逐用例分支见 `02_docs/微服务公开API测试映射.md`。

## 2. 自动门禁

| 门禁 | 实现 | 失败条件 |
| --- | --- | --- |
| 代码路由与清单一致 | `public-api-coverage.test.js` 解析三个 `app.js` | 新增、删除或改名公开路由但未更新清单 |
| 清单无空项 | 每项必须有服务、方法、路径和测试编号 | 重复路由或测试编号为空 |
| 文档映射无空项 | 检查 49 个 `METHOD /path` 均出现在映射文档 | 文档遗漏公开接口 |
| UC 流程完整 | 检查 UC01-UC09 均声明 MAIN/ALT/ERR | 任一用例缺少一种路径 |
| 运行时实际触达 | `api-e2e.test.js` 记录经网关调用的路由 | 49 项中任一路由未执行 |
| 下游阻断 | `docker-build` 依赖全部测试，`kubernetes-deploy` 依赖镜像构建 | 任一测试失败即不构建、不部署 |

无需启动容器的静态门禁：

```bash
npm run test:services:inventory
```

```bash

npm run test:services:inventory
npm run test:services:api

docker compose --env-file .env -f 03_devops/docker-compose.microservices.yml down -v
```
