# 2026-08-28 微服务自动部署与可观测性验证记录

## 验收结论

三个业务微服务和 API 网关已纳入同一条 GitHub Actions 门禁流水线。代码 push 后依次执行独立
服务测试、完整拓扑 API/E2E 回归、带提交 SHA 的镜像构建和推送、Kubernetes 滚动部署、健康/
就绪/版本检查。任一测试失败时，`docker-build` 和 `kubernetes-deploy` 不会运行。

## 自动化链路

```text
push
  -> microservice-test（四服务独立测试）
  -> microservice-api-e2e（网关入口 UC01-UC09 + 所有公开 API）
  -> docker-build（ghcr.io/.../<service>:<commit-sha>）
  -> kubernetes-deploy（kind）
  -> rollout + /health + /ready + /version
```

微服务镜像同时保留不可变的 `${GITHUB_SHA}` 标签和便于课程演示的 `practice` 标签；实际部署使用
SHA 标签。镜像构建参数将 SHA 写入 `SERVICE_REVISION`，部署检查要求 `/version` 返回同一个 SHA，
可证明运行版本就是本次提交。

## 日志与版本查看

```bash
npm run k8s:observe
```

该命令依次显示 Deployment/Pod、镜像、健康检查、就绪检查、版本、最近日志和 Warning Events。
单独排查某个服务：

```bash
kubectl -n softw-microservices logs deployment/product-service --all-containers --prefix --tail=100
kubectl -n softw-microservices describe deployment product-service
kubectl -n softw-microservices get events --sort-by=.lastTimestamp
```

## 真实失败与恢复

2026-08-28 将商品服务临时部署为不存在的镜像：

```bash
kubectl -n softw-microservices set image deployment/product-service \
  product-service=softw/product-service:missing-demo-20260828
kubectl -n softw-microservices rollout status deployment/product-service --timeout=25s
```

rollout 按预期超时。诊断顺序与结论：

1. `get pods`：新 Pod 为 `ImagePullBackOff`，旧 Pod 仍为 Running。
2. `describe pod`：确认失败镜像名为 `missing-demo-20260828`。
3. `get events`：出现 `ErrImagePull`，并明确提示仓库或版本不存在、拉取被拒绝。
4. 服务日志没有新版本启动记录，因此故障发生在应用启动之前，而不是业务代码异常。

原始证据位于 `04_tests/reports/kubernetes-failure/`。恢复命令及结果：

```bash
kubectl -n softw-microservices set image deployment/product-service \
  product-service=softw/product-service:practice
kubectl -n softw-microservices rollout status deployment/product-service --timeout=180s
```

恢复后 `product-service` 为 `1/1 Ready`，API 网关 `/ready` 返回用户、商品、订单三个依赖均为
`ready: true`。这次实验同时验证了滚动部署失败时旧副本继续服务，不会把错误版本直接替换到线上。

## 流水线失败证据

Kubernetes 部署步骤失败时，工作流自动运行 `k8s-collect-failure.sh`，收集工作负载、Events、Pod/
Deployment describe、当前和上一次容器日志，并以 `kubernetes-failure-<sha>` artifact 保留 14 天。
Compose API 回归失败时同样上传 `microservice-api-failure-<sha>` 日志。成功和失败记录均可从 Actions
对应运行页面下载。
