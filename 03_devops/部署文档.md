本项目是一个购物与二手交易平台，包含前后端两个独立服务：

| 服务 | 技术栈 | 端口 | 目录 |

### 1.3 GitHub Pages + Codespaces 部署步骤

#### 1.3.1 启动 Codespace

1. 进入仓库的 `Code -> Codespaces`。
2. 启动现有 `softw-defense-demo` Codespace，或从 `main` 创建新实例。
3. 等待 `.devcontainer/devcontainer.json` 完成初始化。
4. 在终端运行 `sh 03_devops/scripts/codespace-start.sh`。
5. 使用 `curl http://localhost:3001/api/health` 确认 `status=ok`、`database=ok`。

该脚本使用 `03_devops/docker-compose.yml` 启动 MySQL、Express 后端和备用容器前端。数据库迁移和演示商品在容器启动过程中完成。

#### 1.3.2 公开后端端口

1. 打开 Codespaces 底部 `PORTS` 面板。
2. 找到 3001 端口；如果不存在，选择 `Forward a Port` 并输入 `3001`。
3. 右键该端口，选择 `Port Visibility -> Public`。
4. 复制 `https://<CODESPACE_NAME>-3001.app.github.dev` 地址。
5. 在新标签页访问地址后的 `/api/health`，确认公网健康检查成功。

当前已验证地址：

```text

健康：https://softw-defense-demo-5gp6vp6vgjwghv95q-3001.app.github.dev/api/health
```

#### 1.3.3 配置并发布 Pages

进入仓库 `Settings -> Secrets and variables -> Actions -> Variables`，创建或更新：

```text

Value: https://softw-defense-demo-5gp6vp6vgjwghv95q-3001.app.github.dev/api
```

进入 `Actions -> deploy-github-pages -> Run workflow`，选择 `main`。成功后访问：

```text

发布工作流从 `CODESPACE_API_BASE_URL` 构建前端，上传图片 URL 也会解析到 Codespaces 后端。当前发布运行 #33054053025 已成功，公网 E2E 4/4 通过并覆盖 UC01-UC09。

## 2. 小学期 GitHub 协作平台部署与管理补充

### 2.1 平台定位

小学期阶段统一使用 GitHub 进行代码托管、任务管理和持续集成。GitHub Repository 保存交付物，Issues 保存任务与验收证据，GitHub Project「软工小学期」提供看板，GitHub Actions 保存测试、构建和部署检查记录。当前公网演示由 GitHub Pages 前端和 Codespaces 后端/MySQL 组成；Docker 本地与 Kind 环境用于复现和备用演示。

GitHub 必做内容：

- 所有任务建立带编号的 GitHub Issue，并填写负责人、计划日期、验收标准和证据要求。
- 将 Issue 加入 GitHub Project，按 `待启动 -> 开发 -> 测试 -> 部署 -> 已完成` 流转。
- 使用分支和 Pull Request 关联 Issue。
- 通过 GitHub Actions 执行测试、构建和部署检查。
- 保留 Project、Issue、提交、Pull Request 和 Actions 运行记录。

```

流水线还会执行 Playwright E2E、容器镜像构建和 Kubernetes manifest 检查。验收时应引用 GitHub Actions 的实际成功运行链接，不以本地口头说明替代。

`CI_INTERNAL_SERVICE_TOKEN` 四个 GitHub Actions Repository secrets。未配置时流水线应失败，
不能把真实值或固定口令补回工作流文件。

#### 2.5.3 D7-01 微服务 CI/CD 门禁

向 `main`、`develop`、`practice/**` 或 `issue/**` push 会执行完整链路；Pull Request 只执行测试和
镜像构建校验，不推送镜像或部署。`microservice-test` 以矩阵方式让 `user-service`、`product-service`、`order-service` 和
`api-gateway` 分别执行 `npm ci`、`npm test`。`docker-build` 依赖全部单体、前端、浏览器和微服务
测试，七个矩阵项分别构建 backend、frontend、microservice-frontend、网关及三个业务服务镜像。
镜像只推送 `${GITHUB_SHA}` 标签；任一测试失败时整个构建 Job 被跳过，任一镜像失败时
`kubernetes-deploy` 被跳过。

部署 Job 在临时 Kind 集群中执行以下检查：

```text
rollout status -> /health -> /ready -> /version 中的 revision == GITHUB_SHA
```

成功和失败均上传 `kubernetes-deployment-${GITHUB_SHA}` 工件，其中包含 rollout 输出、部署镜像、
Pod/Deployment/Service 状态、Events、describe 和容器日志。手动运行工作流并勾选
`run_failure_drill`，会部署一个不存在的 `user-service` 标签、等待预期失败、采集诊断、回滚并重新验证。

本地干净 Kind 环境的等价流程：

```bash
kind create cluster --name softw-practice --config 03_devops/k8s/kind-config.yaml
set -a
. ./.env
set +a
IMAGE_TAG=$(git rev-parse HEAD)
sh 03_devops/scripts/build-local-images.sh softw "$IMAGE_TAG"
sh 03_devops/scripts/deploy-k8s.sh softw "$IMAGE_TAG"
sh 03_devops/scripts/run-deployment-failure-drill.sh softw "$IMAGE_TAG"
```

端口和集群内检查地址：单体前端 `8080`、单体后端 `3001/api/health`、微服务前端 `8082`、网关
`8081/health`；集群内部网关为 `http://api-gateway:8080`，三个业务服务端口依次为 3101、3102、
3103。恢复单个 Deployment：

```bash
sh 03_devops/scripts/rollback-k8s.sh softw-microservices user-service
sh 03_devops/scripts/rollback-k8s.sh softw-microservices user-service 2 "$IMAGE_TAG"
```

详细证据索引见 `2026-08-31-D7-01-CI-CD部署与回滚验收记录.md`。
