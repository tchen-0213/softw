### 1.1 项目概述

本项目是一个购物与二手交易平台，包含前后端两个独立服务：

| 服务 | 技术栈 | 端口 | 目录 |
|------|--------|------|------|
| 后端 | Node.js + Express + MySQL | 3001 | `backend/` |
| 前端 | React + Vite + Redux | 5173 | `frontend/` |

### 1.2 前置条件

- [Railway 账户](https://railway.app/)
- GitHub/GitLab 仓库（已包含项目代码）
- MySQL 知识（本地开发调试用）

### 1.3 Railway 部署步骤

#### 1.3.1 部署后端服务

**步骤 1：创建新项目**
1. 登录 Railway
2. 点击 "New Project" → "Deploy from GitHub repo"
3. 选择项目仓库，指定 `backend/` 目录

**步骤 2：配置环境变量**

在 Railway 项目的 "Variables" 页面添加以下环境变量：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `PORT` | `3001` | 服务端口 |
| `DB_HOST` | Railway MySQL 提供的主机名 | 自动生成 |
| `DB_PORT` | `3306` | MySQL 端口 |
| `DB_USER` | Railway MySQL 提供的用户名 | 自动生成 |
| `DB_PASSWORD` | Railway MySQL 提供的密码 | 自动生成 |
| `DB_NAME` | Railway MySQL 提供的数据库名 | 自动生成 |
| `JWT_SECRET` | 随机字符串（建议32位以上） | 用于JWT签名 |
| `JWT_EXPIRES_IN` | `30d` | Token有效期 |
| `CORS_ORIGIN` | 前端域名（如 `https://xxx.up.railway.app`） | 允许的跨域来源 |
| `NODE_ENV` | `production` | 生产环境 |

**步骤 3：添加 MySQL 数据库**
1. 在 Railway 项目中添加 "MySQL" 插件
2. Railway 会自动配置数据库连接信息

**步骤 4：启动部署**

Railway 会自动读取 `railway.json` 并执行部署：
```json
{
  "$schema": "https://railway.com/railway.schema.json",
  "build": {
    "builder": "NIXPACKS"
  },
  "deploy": {
    "startCommand": "npm start",
    "restartPolicyType": "ON_FAILURE",
    "restartPolicyMaxRetries": 10
  }
}
```

#### 1.3.2 部署前端服务

**步骤 1：创建新项目**
1. 点击 "New Project" → "Deploy from GitHub repo"
2. 选择项目仓库，指定 `frontend/` 目录

**步骤 2：配置环境变量**

添加以下环境变量：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `PORT` | Railway 分配的端口 | 自动分配 |
| `VITE_API_URL` | 后端服务域名（如 `https://xxx.up.railway.app`） | 后端API地址 |

**步骤 3：启动部署**

Railway 会自动读取 `railway.json` 并执行部署：
```json
{
  "$schema": "https://railway.com/railway.schema.json",
  "build": {
    "builder": "NIXPACKS"
  },
  "deploy": {
    "startCommand": "npm run preview -- --host 0.0.0.0 --port ${PORT}",
    "restartPolicyType": "ON_FAILURE",
    "restartPolicyMaxRetries": 10
  }
}
```

### 1.4 本地开发环境搭建

#### 1.4.1 后端环境

```bash
cd backend

# 安装依赖
npm install

# 创建环境变量文件
cp .env.example .env

# 修改 .env 文件，配置本地 MySQL
# DB_HOST=localhost
# DB_USER=root
# DB_PASSWORD=your_password
# DB_NAME=shopping_platform

# 启动开发服务器
npm run dev
```

#### 1.4.2 前端环境

```bash
cd frontend

# 安装依赖
npm install

# 启动开发服务器（已配置代理到 localhost:3001）
npm run dev
```

### 1.5 数据库初始化

```bash
# 在 backend 目录执行
npm run db:migrate
npm run db:migrate:status
npm run seed
```

迁移版本记录在数据库的 `schema_migrations` 表中。`seed` 会执行 `seedDemoProducts.js` 初始化示例商品；完整答辩数据使用 `npm run seed:scenario`。后端正常启动时也会自动执行所有待处理迁移，迁移失败时健康检查保持 503。

## 2. 小学期 GitHub 协作平台部署与管理补充

### 2.1 平台定位

小学期阶段统一使用 GitHub 进行代码托管、任务管理和持续集成。GitHub Repository 保存交付物，Issues 保存任务与验收证据，GitHub Project「软工小学期」提供看板，GitHub Actions 保存测试、构建和部署检查记录。系统运行演示优先使用 Docker 本地或测试环境。

GitHub 必做内容：

- 所有任务建立带编号的 GitHub Issue，并填写负责人、计划日期、验收标准和证据要求。
- 将 Issue 加入 GitHub Project，按 `待启动 -> 开发 -> 测试 -> 部署 -> 已完成` 流转。
- 使用分支和 Pull Request 关联 Issue。
- 通过 GitHub Actions 执行测试、构建和部署检查。
- 保留 Project、Issue、提交、Pull Request 和 Actions 运行记录。

### 2.2 GitHub Project 与 Issues

当前入口：

```text
仓库：https://github.com/tchen-0213/softw
```

```text

```

### 2.4 分支与提交规范

建议分支：

| 分支 | 用途 |
| --- | --- |
| main | 稳定交付分支 |
| dev | 日常集成分支 |
| feature/docs-github-projects | GitHub Projects 与文档完善 |
| feature/security-hardening | 安全加固 |
| feature/performance | 性能优化 |
| feature/testing | 测试体系 |

提交信息建议格式：

```text
docs: 完善小学期 GitHub Projects 使用说明
test: 补充接口测试用例
perf: 优化商品列表查询
security: 增加上传文件类型限制
refactor: 调整后端模块结构
```

### 2.5 GitHub Actions 流水线

主流水线配置位于 `.github/workflows/ci-cd.yml`。推送到 `main`、`develop`、`practice/**` 或向 `main`、`develop` 提交 Pull Request 时自动运行。

#### 2.5.2 前端依赖安装与构建

```bash

```

#### 2.5.3 后续测试步骤

后端测试命令：

```bash
npm --prefix backend test
npm --prefix backend run test:api
```

前端测试与构建命令：

```bash
npm --prefix frontend run test:unit
npm --prefix frontend run build
```

流水线还会执行 Playwright E2E、容器镜像构建和 Kubernetes manifest 检查。验收时应引用 GitHub Actions 的实际成功运行链接，不以本地口头说明替代。

### 2.7 可选云端部署方案

如果后续学校要求必须云端运行，可扩展为：

- 华为云 ECS：部署 Node.js 后端和前端静态资源。

- CodeArts Deploy：自动发布到 ECS。
