# 2026-08-31 D7-01 CI/CD 部署与回滚验收记录

## 验收范围

对应 GitHub Issue [#18](https://github.com/tchen-0213/softw/issues/18)。本记录覆盖四个微服务独立安装与测试、
七个版本化镜像、测试失败门禁、Kind 自动部署、健康/就绪/版本检查、受控部署失败诊断和回滚。

## 流水线设计证据

| 阶段 | 实现 | 门禁 |
| --- | --- | --- |
| 四个微服务测试 | `microservice-test` 的四项矩阵分别执行 `npm ci`、`npm test` | 任一项失败则 `docker-build` 不运行 |
| 七镜像构建 | `docker-build` 的七项矩阵分别构建并推送 | 只使用完整 `github.sha` 标签，不发布 `latest` |
| Kind 部署 | `kubernetes-deploy` 调用 `deploy-k8s.sh` | 仅全部测试和七项镜像构建成功后运行 |
| 部署验收 | rollout、`/health`、`/ready`、`/version` | revision 必须等于部署镜像 SHA |
| 诊断工件 | 成功或失败均执行状态采集并上传 | 工件保留 14 天，不写出 Secret 值 |

工作流：`.github/workflows/ci-cd.yml`。

## 干净环境复现

前置环境：Git、Docker、Kind、kubectl；Node.js 20 只用于脱离容器运行测试。四项运行密钥通过环境变量
提供，不进入仓库：

```text
SOFTW_MYSQL_ROOT_PASSWORD
SOFTW_DB_PASSWORD
SOFTW_JWT_SECRET
SOFTW_INTERNAL_SERVICE_TOKEN
```

执行：

```bash
kind create cluster --name softw-practice --config 03_devops/k8s/kind-config.yaml
set -a
. ./.env
set +a
IMAGE_TAG=$(git rev-parse HEAD)
sh 03_devops/scripts/build-local-images.sh softw "$IMAGE_TAG"
sh 03_devops/scripts/deploy-k8s.sh softw "$IMAGE_TAG"
```

`build-local-images.sh` 构建并向 Kind 加载七个 `softw/<name>:<commit-sha>` 镜像；脚本拒绝 `latest`
和 `practice`。部署输出保存在 `04_tests/reports/kubernetes-deployment/`，其中版本接口必须返回同一 SHA。

## 受控部署失败、定位与回滚

执行：

```bash
sh 03_devops/scripts/run-deployment-failure-drill.sh softw "$IMAGE_TAG"
```

实验给 `user-service` 设置 `softw/user-service:missing-<commit-sha>`。预期现象是新 Pod 出现
`ErrImagePull`/`ImagePullBackOff`，`rollout status` 超时；诊断脚本保存 Events、Pod/Deployment describe、
ReplicaSet 和当前/previous 日志。随后 `rollout undo`，等待恢复完成，确认镜像回到原 SHA，并重新检查四个
服务的健康、就绪和版本接口。

也可在 Actions 页面手动运行 `softw-ci-cd`，勾选 `run_failure_drill`。手动运行复用此前 push 发布的
SHA 镜像，不覆盖不可变标签。实验返回成功表示“预期部署失败已出现且回滚验证成功”，原始材料位于同一个
`kubernetes-deployment-<sha>` 工件的 `failure-drill/` 目录。
