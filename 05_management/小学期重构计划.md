# 小学期系统重构与优化计划

## 1. 背景

本项目为购物与二手交易平台，已在大作业阶段完成用户、商品、二手交易、购物车、订单、评价、店铺、聊天、地址、上传等基础功能。小学期阶段在现有系统基础上使用 GitHub Repository、Issues、Projects 和 Actions 统一管理代码、任务与持续集成，采用敏捷过程模型进行项目管理，重点提升系统的非功能属性，包括性能、并发能力、安全性、可维护性、可测试性和可观测性。

## 4. 技术路线

小学期采用稳定增强路线，不进行一次性大规模推倒重写。总体策略为保留现有 React + Express + Sequelize + MySQL 技术栈，在现有功能可运行的前提下进行模块化重构、工程化增强和非功能属性提升。

主要原则：

- 保留现有前后端分离架构，降低重构风险。
- 优先完善文档、测试、部署和敏捷过程记录。
- 后端先进行模块边界梳理和服务化设计，再按风险拆分核心模块。
- 非功能属性提升以可证明为目标，通过测试、压测、日志、监控和对比记录体现。
- GitHub Repository、Issues、Projects 和 Actions 分别用于代码托管、工作项、看板和持续集成。

## 5. 工作包拆解

### 5.1 GitHub 协作平台建设

- 建立 GitHub Project 并关联当前仓库。
- 以 Issues 建立带编号的工作项并分配负责人。
- 建立 `待启动 -> 开发 -> 测试 -> 部署 -> 已完成` 看板流程。
- 配置 Backlog、优先级、负责人、Roadmap 和每日视图。
- 使用 GitHub Actions 完成拉取代码、安装依赖、测试、前端构建和部署检查。
- 在敏捷记录文档中保留任务流转和会议记录。

### 5.2 文档完善

- 更新需求规格说明书中的非功能需求。
- 更新概要设计说明书中的重构架构与模块边界。
- 更新详细设计说明书中的安全、性能、测试和监控设计。
- 更新测试文档，补充自动化测试、性能测试和安全测试。
- 更新部署文档，补充 GitHub Projects 与 Actions 平台流程。
- 新增小学期重构计划、GitHub Projects 使用说明、敏捷开发记录、微服务拆分设计、性能优化与压测方案、安全加固方案。

### 5.3 测试环境与测试体系

- 建立本地测试环境启动流程。
- 准备接口测试用例。
- 设计自动化测试框架，后端优先采用 Jest + Supertest。
- 设计性能测试脚本，优先覆盖登录、商品列表、商品详情、创建订单。
- 建立缺陷记录表，记录发现、修复、验证状态。

### 5.4 模块化重构与微服务准备

- 梳理后端模块边界：用户、商品、订单、店铺、评价、聊天、上传。
- 提取公共中间件：鉴权、错误处理、参数校验、日志、限流。
- 设计 API 网关和服务拆分方案。
- 稳定路线下优先完成代码结构治理和网关原型设计，不强制全量拆分。

### 5.5 高性能与高并发优化

- 为商品、订单、用户等核心表补充索引设计。
- 优化卖家订单查询，避免全表查询后内存过滤。
- 商品列表和推荐接口增加缓存设计。
- 下单库存扣减增加事务和并发控制说明。
- 编写压测计划和压测报告模板。

### 5.6 安全性提升

- JWT 密钥必须由环境变量提供。
- 增加请求参数校验。
- 增加接口限流。
- 增加安全响应头。
- 上传文件限制类型、大小和路径。
- 审计用户、订单、店铺、评价等接口权限。
- 避免生产环境向前端返回详细异常堆栈。

### 5.7 可观测性与监控

- 增加统一请求日志。
- 增加统一错误处理中间件。
- 设计 Trace ID，便于定位一次请求链路。
- 增加健康检查内容：服务状态、数据库连接状态、版本、启动时间。
- 设计性能指标：请求数量、响应时间、错误率、慢接口。

## 6. 验收成果

小学期结束时应形成以下成果：

- GitHub Project、Issues、提交和 Actions 运行记录。
- 代码提交记录和重构说明。
- 完善后的需求、设计、测试、部署文档。
- 自动化测试或接口测试记录。
- 性能压测报告和优化前后对比。
- 安全加固说明和测试结果。
- 总结汇报材料。
