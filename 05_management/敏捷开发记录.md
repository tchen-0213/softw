# 敏捷开发记录

> 平台口径说明：任务统一使用 GitHub Issues、GitHub Project「软工小学期」和 GitHub Actions 管理，现行规则见 `GitHub-Projects使用说明.md`。

## 1. 敏捷模型

小学期阶段采用 Scrum 与看板结合的方式进行管理。Scrum 用于规划 8 月 25 日至 9 月 4 日的两个迭代，看板用于跟踪每日任务状态。

看板状态：

```text
待办 -> 进行中 -> 代码评审 -> 测试中 -> 已完成
```

## 3. Sprint 计划

### Sprint 1：准备阶段

时间：8 月 25 日至 8 月 29 日。

目标：

- 完成 GitHub Project 创建并关联仓库与 Issues。
- 建立 Scrum 看板和任务清单。
- 完成现有系统梳理。
- 完成小学期核心文档补充。
- 完成测试和部署环境方案。
- 完成微服务拆分、性能优化、安全加固方案设计。

交付物：

- GitHub Project 和 Issues。
- 小学期重构计划。
- GitHub Projects 使用说明。
- 微服务拆分设计。
- 性能优化与压测方案。
- 安全加固方案。
- 更新后的测试和部署文档。

### Sprint 2：重构优化阶段

时间：8 月 31 日至 9 月 4 日。

目标：

- 完成稳定路线下的模块化重构。
- 完成核心安全加固。
- 完成核心性能优化设计和验证。
- 完成测试验证和缺陷修复。
- 完成 GitHub Actions 流水线验证。
- 完成总结汇报。

交付物：

- 重构代码提交记录。
- 测试记录和缺陷记录。
- 性能压测报告。
- 安全加固记录。
- GitHub Actions 流水线执行记录。
- 总结汇报材料。

## 5. 风险跟踪

| 风险 | 影响 | 应对措施 | 状态 |
| --- | --- | --- | --- |
| GitHub Project 成员权限不完整 | 影响任务更新和每日看板证据 | 由项目所有者邀请成员并逐一验证编辑权限 | 待跟踪 |
| 微服务拆分范围过大 | 影响系统稳定性 | 采用稳定增强路线，优先模块化和网关设计 | 已规避 |
| 测试环境不稳定 | 影响验证和演示 | 保留本地环境启动脚本和演示数据 | 待跟踪 |
| 性能优化缺少量化结果 | 影响汇报说服力 | 使用压测脚本记录优化前后指标 | 待跟踪 |
| 安全加固引入兼容问题 | 影响原有功能 | 每项安全改造后执行回归测试 | 待跟踪 |
