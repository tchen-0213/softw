## 第 4 页 · 三个业务微服务（职责 / 划分 / 接口 / 表 / 失败）

```
前端 → API Gateway（不算业务服务）
        ├─ user-service    → softw_users
        ├─ product-service → softw_catalog + uploads
        └─ order-service   → softw_orders
```

划分按 **身份 / 可交易资源 / 交易过程**，不是 12 个用例 12 个服务。

| 服务 | 职责 | 库 |
| --- | --- | --- |
| user-service | 注册登录、资料、密码、地址、角色、信用 | softw_users：Users, Addresses |
| product-service | 商品、二手、店铺、评价、聊天、议价、图片、库存 | softw_catalog：Products, Shops, Evaluations, Chat* , InventoryReservations；uploads/ |
| order-service | 下单、支付、取消、发货、收货、状态机 | softw_orders：Orders |
| API Gateway | 路由、JWT 透传、超时、CORS | 无库 |

网关前缀：`/api/users` `/api/addresses` → user；`/api/products` `/api/secondhand` `/api/shops` `/api/evaluations` `/api/chats` `/api/uploads` → product；`/api/orders` → order。

每张表只由一个服务写入；订单保存商品项和地址 **快照**，不跨库联表。内部接口要 `X-Internal-Token`。

失败处理：

- 网关超时/断开 → HTTP **503**，不伪造成功
- 库存预留失败 → 不创建订单
- 释放/完成按 reservationId **幂等**
- 停 product-service：商品 **503**「依赖服务暂不可用」；订单依赖 **206**「商品信息暂不可用，订单查询保持可用」；网关/用户/订单仍存活
