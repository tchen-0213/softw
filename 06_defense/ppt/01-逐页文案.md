## 第 5 页 · 业务微服务：职责、划分依据、接口、表归属

对应助教：「每个业务微服务的职责、划分依据、接口调用和数据表归属」

```
前端 → API Gateway（不算业务服务）
        ├─ user-service    → softw_users
        ├─ product-service → softw_catalog + uploads
        └─ order-service   → softw_orders
```

划分依据：身份 / 可交易资源 / 交易过程。**不是** 12 个用例 12 个服务。

| 服务 | 职责 | 划分依据 | 库与表 |
| --- | --- | --- | --- |
| user-service | 注册登录、资料、密码、地址、角色、信用 | 身份与账号生命周期 | softw_users：Users, Addresses |
| product-service | 商品、二手、店铺、评价、聊天、议价、图片、库存 | 可交易资源 | softw_catalog：Products, Shops, Evaluations, Chat*, InventoryReservations；uploads/ |
| order-service | 下单、支付、取消、发货、收货、状态机 | 交易过程与快照 | softw_orders：Orders, OrderSellers |
| API Gateway | 路由、JWT 透传、超时、CORS | 统一入口，不计入 3 | 无库 |

接口调用（网关前缀）：

- `/api/users` `/api/addresses` → user-service
- `/api/products` `/api/secondhand` `/api/shops` `/api/evaluations` `/api/chats` `/api/uploads` → product-service
- `/api/orders` → order-service
- 跨服务：订单 → 商品 库存预留/释放/完成；商品/订单 → 用户 身份快照/信用。内部接口 `X-Internal-Token`。
- 每张表只由一个服务写入；订单保存商品项和地址快照，不跨库联表。

配图：`P03-微服务划分.png`（尽量大）、`P01-组件架构.png`（可作对照）

## 第 6 页 · 调用失败时的处理办法

对应助教：「以及调用失败时的处理办法」

| 场景 | 处理 |
| --- | --- |
| 网关超时或上游断开 | HTTP **503**，不伪造成功 |
| 库存预留失败（无货/超时） | 不创建订单；超时 503 |
| 释放 / 完成预留 | 按 reservationId **幂等** |
| 停 product-service | 商品 **503**「依赖服务暂不可用」；订单依赖检查 **206** `degraded`「商品信息暂不可用，订单查询保持可用」；网关/用户/订单仍 1/1 |
| 内部库存、信用、购买证明 | 必须带 token，外部不能直打 |

实验：`npm run experiment:fault`；恢复后商品 200、HPA 重建、无残留。细节在录屏。
