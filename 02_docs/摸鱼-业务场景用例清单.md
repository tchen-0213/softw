第 13 组 · 校园新品与二手交易平台

重点用例为 UC01、UC02、UC04

## 1. 用例总表


| 编号   | 业务场景（用例）        | 参与者     | 可验证结果                |
| ---- | --------------- | ------- | -------------------- |
| UC01 | 完成平台注册并建立可用登录身份 | 游客、注册用户 | 获得登录令牌，可访问个人中心       |
| UC02 | 找到符合条件的在售商品     | 游客、买家   | 列表按关键词与筛选条件返回目标商品    |
| UC03 | 确认商品信息并加入待结算购物车 | 买家      | 详情可查看，购物车出现指定商品与数量   |

| UC06 | 完成店铺认证并维护店铺和商品  | 卖家      | 店铺进入营业状态，资料与本人商品变更生效 |
| UC07 | 对已完成交易进行评价和回复   | 买家、卖家   | 评价发布并可查询，卖家可回复       |

**实现说明：**

1. UC04 支付为站内模拟支付；物流由卖家填写公司与运单号，在站内记录发货与收货状态。
2. UC06 店铺认证为提交完整资料后系统完成认证并进入营业。

## 2. 用例说明



### UC01 完成平台注册并建立可用登录身份


| 项目    | 说明                                                                                                               |
| ----- | ---------------------------------------------------------------------------------------------------------------- |
| 对应需求  | REQ01 用户身份建立与认证                                                                                                  |
| 参与者   | 游客、注册用户                                                                                                          |
| 触发条件  | 游客需要使用下单、发布、聊天等需登录的功能                                                                                            |
| 前置条件  | 用户当前未登录；注册时邮箱与用户名未被占用                                                                                            |
| 主成功流程 | 1. 游客填写用户名、邮箱、手机号和密码。2. 系统校验必填项、邮箱格式和密码长度。3. 系统创建用户并加密保存密码。4. 系统返回登录令牌和用户信息。5. 用户使用邮箱和密码再次登录。6. 系统验证通过后允许访问个人中心。 |
| 备选流程  | 已注册用户直接登录；登录后可更新昵称、手机号或密码。                                                                                       |
| 异常流程  | 缺少必填项、邮箱格式错误、密码过短或用户已存在时拒绝注册；用户不存在、密码错误或令牌无效时拒绝登录或访问个人中心。                                                        |
| 可验证结果 | 返回有效 JWT；个人资料可查询；响应中不以明文返回密码。                                                                                    |




### UC02 找到符合条件的在售商品


| 项目    | 说明                                                                                           |
| ----- | -------------------------------------------------------------------------------------------- |
| 对应需求  | REQ02 商品浏览、搜索、筛选和排序                                                                          |
| 参与者   | 游客、买家                                                                                        |
| 触发条件  | 用户输入关键词或选择筛选、排序条件                                                                            |
| 前置条件  | 系统中存在商品数据；后端与数据库可访问                                                                          |
| 主成功流程 | 1. 用户进入首页或搜索页。2. 输入关键词并选择分类、价格或排序条件。3. 系统查询符合条件且状态为在售的商品。4. 系统返回分页结果。5. 页面展示商品名称、价格、图片等摘要信息。 |
| 备选流程  | 不输入关键词时浏览全部在售商品；可切换至二手商品范围；无匹配结果时展示空结果。                                                      |
| 异常流程  | 非法分页或筛选参数由系统归一化处理；查询失败时返回错误提示，不展示伪造结果。                                                       |
| 可验证结果 | 返回结果满足关键词与筛选条件；默认不展示不可售商品；目标商品可进入详情页。                                                        |




### UC03 确认商品信息并加入待结算购物车


| 项目    | 说明                                                                                                |
| ----- | ------------------------------------------------------------------------------------------------- |
| 对应需求  | REQ03 商品详情与购物车                                                                                    |
| 参与者   | 买家                                                                                                |
| 触发条件  | 用户从商品列表选择一件商品并准备购买                                                                                |
| 前置条件  | 目标商品存在且可访问                                                                                        |
| 主成功流程 | 1. 用户打开商品详情。2. 系统展示名称、价格、库存、卖家、图片、二手属性及评价。3. 用户选择购买数量。4. 用户加入购物车。5. 系统保存商品、数量与价格。6. 购物车显示正确小计与总额。 |
| 备选流程  | 商品已在购物车中时合并或调整数量；用户可增减数量、删除商品或继续结算。                                                               |
| 异常流程  | 商品不存在时给出提示；数量小于 1、超过库存或商品不可售时，不允许形成有效结算项。                                                         |
| 可验证结果 | 详情内容与后端数据一致；购物车出现指定商品与数量；金额计算正确。                                                                  |




### UC04 完成订单创建、支付、发货和收货


| 项目    | 说明                                                                                                                                         |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 对应需求  | REQ04 订单交易闭环                                                                                                                               |
| 参与者   | 买家、卖家                                                                                                                                      |
| 触发条件  | 买家从购物车或商品详情发起结算                                                                                                                            |
| 前置条件  | 买家已登录；商品在售且库存充足；买家已选择有效收货地址                                                                                                                |
| 主成功流程 | 1. 买家确认商品、数量、地址和支付方式。2. 系统复核商品状态与库存。3. 系统创建待付款订单并扣减库存。4. 买家完成站内模拟支付，订单变为待发货。5. 卖家填写物流公司与运单号并发货，订单变为待收货。6. 买家确认收货，订单变为已完成。7. 二手商品售罄后标记为已售出。 |
| 备选流程  | 买家可在允许的状态下取消订单，系统恢复库存；普通商品可购买多个数量；二手商品库存归零后进入相应售出状态。                                                                                       |
| 异常流程  | 商品不存在、不可售或库存不足时拒绝创建订单；非买家不能支付或确认收货；非卖家不能发货；错误状态下不能重复支付、发货或确认；物流信息不完整时拒绝发货。                                                                 |
| 可验证结果 | 订单状态按「待付款 → 待发货 → 待收货 → 已完成」正确转换；支付状态、物流记录与库存变化可查询。                                                                                        |




### UC05 发布一件可交易的二手商品


| 项目    | 说明                                                                                                                |
| ----- | ----------------------------------------------------------------------------------------------------------------- |
| 对应需求  | REQ05 二手商品发布                                                                                                      |
| 参与者   | 卖家                                                                                                                |
| 触发条件  | 用户进入发布页面并填写二手商品信息                                                                                                 |
| 前置条件  | 用户已登录，且店铺已完成认证                                                                                                    |
| 主成功流程 | 1. 卖家填写名称、描述、价格、库存、分类、成色、使用时间与交易地点。2. 可选上传允许格式的图片。3. 系统校验店铺资格与商品字段。4. 系统创建带二手标识的在售商品。5. 页面进入商品详情。6. 商品可在二手列表中被检索。 |
| 备选流程  | 卖家可启用或关闭议价；发布后可修改商品资料与上下架状态。                                                                                      |
| 异常流程  | 未登录、店铺未认证、字段不完整、状态非法或上传文件类型不允许时拒绝发布；其他用户不能修改或删除该商品。                                                               |
| 可验证结果 | 新商品具有二手标识及成色、地点等信息；列表与详情均可访问；卖家归属正确。                                                                              |




### UC06 完成店铺认证并维护店铺和商品


| 项目    | 说明                                                                                                          |
| ----- | ----------------------------------------------------------------------------------------------------------- |
| 对应需求  | REQ06 店铺认证和经营管理                                                                                             |
| 参与者   | 卖家                                                                                                          |
| 触发条件  | 用户希望发布和管理商品                                                                                                 |
| 前置条件  | 用户已登录                                                                                                       |
| 主成功流程 | 1. 用户打开店铺中心。2. 填写经营者姓名、证件号、经营地址和证明图片。3. 系统检查必填资料并完成认证。4. 店铺状态变为营业中。5. 卖家修改店铺名称、简介等资料。6. 卖家创建、修改、上下架或删除本人商品。 |
| 备选流程  | 已认证卖家直接进入店铺中心；公开店铺页可查看卖家资料与商品。                                                                              |
| 异常流程  | 认证资料缺失时拒绝提交；未认证店铺不能发布商品；卖家不能修改或删除他人商品；非法商品状态被拒绝。                                                            |
| 可验证结果 | 店铺认证状态、营业状态与资料更新可查询；商品变更仅作用于当前卖家的商品。                                                                        |




### UC07 对已完成交易进行评价和回复


| 项目    | 说明                                                                                       |
| ----- | ---------------------------------------------------------------------------------------- |
| 对应需求  | REQ07 交易评价与信用反馈                                                                          |
| 参与者   | 买家、卖家                                                                                    |
| 触发条件  | 买家在订单完成后进入评价                                                                             |
| 前置条件  | 当前用户为该订单买家；订单状态为已完成；商品属于该订单；此前未对该商品重复评价                                                  |
| 主成功流程 | 1. 买家打开待评价订单。2. 填写评分和文字内容。3. 系统验证订单与商品关系。4. 系统发布评价。5. 商品评价列表与用户评价历史可查询。6. 卖家可对收到的评价进行回复。 |
| 备选流程  | 评价可附带图片；买卖双方在权限允许时可继续回复。                                                                 |
| 异常流程  | 订单不存在、非订单买家、订单未完成、商品不在订单中、重复评价或回复内容为空时拒绝操作；无关用户不能回复。                                     |
| 可验证结果 | 评价状态为已发布，评分与内容可查询；重复提交不产生第二条评价；合法回复被保存。                                                  |




### UC08 买卖双方通过会话完成咨询和议价


| 项目    | 说明                                                                                              |
| ----- | ----------------------------------------------------------------------------------------------- |
| 对应需求  | REQ08 商品咨询与议价处理                                                                                 |
| 参与者   | 买家、卖家                                                                                           |
| 触发条件  | 买家从商品详情发起私聊或议价                                                                                  |
| 前置条件  | 买卖双方均已登录；商品存在；买家不是该商品卖家                                                                         |
| 主成功流程 | 1. 买家从商品详情创建或进入会话。2. 双方发送文本消息。3. 买家输入有效金额并发送议价申请。4. 系统保存待处理申请。5. 卖家查看会话并同意或拒绝。6. 系统保存处理结果至会话记录。 |
| 备选流程  | 同一商品与同一买卖双方复用已有会话；卖家可拒绝议价；已购买且已支付的商品可发起退款申请，由卖家同意或拒绝。                                           |
| 异常流程  | 用户不能与自己的商品私聊；非会话成员不能查看或发言；商品关闭议价、金额无效、非买家发起申请、非卖家处理申请或重复处理时拒绝操作。                                |
| 可验证结果 | 会话双方、消息顺序与申请状态可查询；议价最终状态为已同意或已拒绝。                                                               |




### UC09 维护并在结算时使用收货地址


| 项目    | 说明                                                                                     |
| ----- | -------------------------------------------------------------------------------------- |
| 对应需求  | REQ09 收货地址维护与结算使用                                                                      |
| 参与者   | 买家                                                                                     |
| 触发条件  | 用户在个人中心或结算页新增、修改、删除或选择地址                                                               |
| 前置条件  | 用户已登录                                                                                  |
| 主成功流程 | 1. 用户打开地址管理。2. 新增收货人、电话和详细地址。3. 可设置一个默认地址。4. 系统保存当前用户地址列表。5. 结算页读取地址。6. 用户选择地址并用于创建订单。 |
| 备选流程  | 用户可编辑、删除地址或更换默认地址；无地址时可从结算页新增。                                                         |
| 异常流程  | 未登录时拒绝读取或保存；提交内容非法时拒绝保存；缺少姓名、电话或详细地址的条目不进入保存结果；地址按账号隔离，其他账号不能读取。                       |
| 可验证结果 | 再次读取后地址数据保持一致；默认地址唯一；订单保存所选收货信息。                                                       |
